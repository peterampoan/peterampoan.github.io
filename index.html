Self-service branch onboarding portal

JeonSoft · Lead
problem
A VIP client with many branches requested new branch setups often. Each one was manual: creating the account, setting up a blank database, importing it to AWS and scheduling its backups. Only a few senior engineers had AWS access, and they were also handling their own tasks and urgent issues. The client usually waited until the next day or longer, depending on workload.
solution
I led the build of a self-service portal where the client enters the new branch's details. The back end then handles the rest automatically:
  • Restores a baseline database to AWS
  • Creates the database instance and its backup schedule
  • Generates the branch account
  • Records the new branch for billing
result
The client sets up new branches on their own, whenever they need them, instead of waiting a day or more. Senior engineers no longer handle routine setups and can focus on development and urgent issues.

Ruby on Rails · MSSQL · AWS · Automation

Speeding up a million-row custom report

JeonSoft · Sole developer
problem
A custom report combined employee records, timesheets (rendered hours, OT, undertime, leaves) and forecast billable amounts. It ran across thousands of employees and millions of timesheet entries, and could take around 30 minutes to load depending on the date range. The UI also made a separate back-end request every time a row was expanded.
solution
  • Used the execution plan in SQL Server Management Studio to find what was making the query slow.
  • Fetched all records for the date range in a single query instead of one request per expanded row.
  • Optimized the SQL with proper indexes, tighter WHERE clauses, and by dropping columns that only added weight.
  • Reworked the front end: it renders the main rows (e.g. dates) first. The back end then returns every record for the date range in one response, and JavaScript groups and maps those results into each row's details, so expanding a row needs no extra request.
result
The per-row round trips are gone, the query does far less work, and expanding a row is instant because its details are already loaded.

MSSQL · SSMS execution plans · Query optimization · Indexing · Ruby on Rails · Webix
